# CC 与 HTTP/HTTPS 业务端口防护

进入“防护规则 → 自定义规则”，在同一页签中配置 CC 防护和业务端口防护，需要防护规则权限。默认关闭，勾选启用后可编辑参数，点击相应保存按钮后生效。两个功能独立保存，保存 CC 不会覆盖另一个管理员正在修改的端口策略。

## CC 防护

“防护绑定”可选指定域名、指定目标 IP 或全部业务入口。指定域名时，可从输入建议中选择已配置的受保护域名，也可手动填写完整域名或单层通配符，不含协议、端口和路径；大小写、末尾点和中文域名会归一化。仅匹配请求的 Host，不信任 X-Forwarded-Host。通配域名下每个实际域名分别按访客 IP 计数、封禁，互不影响。

指定目标 IP 时，填写 WAF 接收业务连接的实际本地 IPv4 / IPv6 地址，不是访客 IP、源站 IP 或 CIDR，也不能填写 0.0.0.0 / ::。系统使用实际连接目的地址匹配，不用客户端 Host 伪造地址。经过 NAT 时填写 NAT 后服务器看到的本地 IP。只有匹配绑定目标的请求才参与 CC 计数，其他入口继续执行原有防护。域名绑定不自动添加站点域名配置、DNS 或 HTTPS 证书；这些仍在“站点配置”完成。

CC 和业务端口防护各支持最多 100 条策略。点击“新增 CC 策略”或“新增业务端口策略”，填写名称、绑定目标和阈值后保存；列表支持编辑、启停、删除。升级自动保留原有策略及启停状态。各条策略独立计数，多个策略同时匹配时必须全部通过，任意一条拒绝即拦截；停用或修改策略后重新开始计数。

启用中的策略禁止删除，须先停用；接口也会拒绝直接删除启用中的策略（409）。正在编辑的策略，其列表中的编辑、启停、删除按钮暂时禁用，保存或“取消编辑 / 重置”后恢复，避免覆盖未保存内容。该编辑锁定仅针对当前页面，不是跨用户的全局编辑锁。

业务端口策略也可绑定域名或目标 IP，并选择 HTTP、HTTPS 或全部协议，以及具体业务监听端口（留空匹配全部）。例如为 a.example.com 的 HTTPS 8443 和 b.example.com 的 HTTPS 9443 分别配置策略。这里的端口必须是 WAF 实际监听端口；策略不会新建监听器，仍需配置服务监听和 Docker 端口映射。

按连接对端 IP、固定统计窗口累计请求。默认窗口 10 秒、100 次，超过后临时封禁 60 秒。支持窗口 1～3600 秒、阈值 1～100000 次、封禁 1～86400 秒。

例如设置窗口 10 秒、最大 30 次、封禁 120 秒：同一来源在窗口内前 30 次继续后续检查，第 31 次返回 429，随后封禁期间返回 429 并携带 Retry-After（剩余秒数）。封禁到期后，下一次请求重新开始计数。窗口是首次请求开始的固定窗口，窗口边界可能出现突发，不是滑动窗口。

计数包括到达 WAF HTTP/HTTPS 应用入口的请求，不根据 Cookie、查询参数或 X-Forwarded-For 区分用户。前置代理时会按代理 IP 统计，请根据实际接入方式设置阈值，避免误封共享出口。IP 状态最多 20000 个，容量耗尽时新来源返回 429；已过期的空闲状态自动回收。

CC 独立于观察模式和攻击特征开关，命中直接阻止。自定义放行规则不绕过 CC；站点原有“每 IP 每分钟请求数”也继续执行，实际以先命中的限制为准。修改防护配置会清空 CC 状态，重启也会清空。

## 业务端口防护

未限定协议和端口的策略自动作用于 WAF HTTP 入口和当前启用的 HTTPS 入口，包括变更后的 HTTPS 端口；指定端口的策略仅匹配该实际监听端口，变更监听端口后须同步修改策略。开发环境同样作用于开发业务入口。管理入口与 Ubuntu 上其他服务端口不受影响。

- 允许来源：每行一个 IPv4、IPv6 或 CIDR；留空允许所有未被禁止的来源，填写后其他来源返回 403。
- 禁止来源：每行一个 IP / CIDR，优先于允许来源，即使同时在允许列表中也拒绝，返回 403。
- 每 IP 最大并发请求：默认 20，上限 10000，达到后新请求返回 429。
- 入口最大并发请求：默认 1000，上限 50000，达到后新请求返回 503。

CIDR 按网络地址归一化，例如 `192.0.2.10/24` 保存为 `192.0.2.0/24`。IPv4 和 IPv6 应分别配置需要的来源范围；IPv4 网段不自动代表 IPv6 来源。

并发统计的是正在处理的 HTTP 请求，包括读取上传内容、访问源站、发送响应；完成、出错或取消后释放额度。它不统计已建立但未发送请求的 TCP 连接或空闲 Keep-Alive，也不提供 TCP SYN、UDP 洪泛或链路带宽耗尽防护。功能在应用层执行，不修改 Ubuntu nftables/UFW，不关闭或打开主机端口，也不是通用主机防火墙。

## 生效范围与顺序

依次检查匹配的业务端口策略（来源控制、并发准入），再检查匹配的 CC 策略，随后执行原有方法、域名、每分钟限流、请求大小、自定义规则和系统特征检测。后续策略拒绝时释放前面策略已占用的并发额度。

所有 HTTP/HTTPS 请求共用当前数据库配置，但每个代理进程独立保存计数、封禁和并发状态。HTTP 与 HTTPS 是独立进程，不能将阈值理解为跨入口或集群共享限额；多实例部署也不会自动同步这些运行计数。策略本身支持 SQLite / PostgreSQL，并随数据库迁移和发布快照备份。

此功能只处理 WAF 反向代理业务入口。交换机镜像旁挂与透明串联的数据平面不使用本策略，仍使用已有检测逻辑；不会因勾选本功能就阻断第三方 HTTPS。

## 验证与排查

建议在本地开发或测试站点先验证，然后按实际用户访问频率及源站容量设置生产阈值。生产默认不自动添加封禁来源或启用限流。

1. 在自定义规则页签新增 CC 策略，设置测试阈值并保存，对匹配业务入口连续请求，确认阈值后出现 429、Retry-After 和关联请求编号。
2. 新增业务端口策略并加入测试来源禁止项，保存后匹配请求应返回 403；管理页面仍可打开，便于修改或关闭策略。
3. 采用延迟响应测试源站发起并发请求，确认并发阈值命中及请求完成后的恢复。
4. 在“访问审计”按“已拦截”筛选，并通过编号定位：

| 规则编号 | 含义 |
| --- | --- |
| CC_RATE | 超过窗口请求阈值，开始临时封禁 |
| CC_BAN | 临时封禁仍有效 |
| CC_CAPACITY | CC 来源跟踪容量已满 |
| PORT_SOURCE | 无法识别有效来源 IP |
| PORT_DENY | 命中禁止来源 |
| PORT_ALLOW | 不在允许来源范围 |
| PORT_CONCURRENT | 每 IP 并发请求超限 |
| PORT_CAPACITY | 当前业务入口总并发超限 |
| TRAFFIC_PROTECTION | 管理员保存策略的配置变更事件 |

多策略命中的规则编号追加具体策略 ID，例如 `CC_RATE:CC-0123456789abcdef`，可对应到策略列表接口返回的 ID。命中及配置变更沿用已有日志转发。高频拒绝也会产生审计记录，应监控数据库负载、磁盘增长和日志积压。本功能是应用层流量限制，上线前仍需结合硬件、带宽、负载均衡和实际请求压测验证承载能力。
