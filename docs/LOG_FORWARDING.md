# 日志服务器转发

“启用日志转发”未勾选时，接收服务器、端口、协议、格式及格式附加字段均禁止编辑，测试按钮禁用；勾选后恢复。切换开关保留字段内容。点击“保存日志配置”后实际启用或停用，未保存的勾选变化仅控制当前表单。保存和刷新状态按钮始终可用。

在“系统配置 → 日志配置”填写接收服务器 IPv4/IPv6 地址、端口和协议，选择格式后保存。默认关闭；保存立即生效，无需重启。测试按钮使用当前填写的参数发送单条测试消息，不会保存草稿。请在接收端确认收到，再启用。

支持 UDP、TCP、TCP + TLS。TCP/TLS 每条消息以 LF 换行结束，接收服务器须启用相应分帧方式。TLS 验证系统信任链和证书 IP SAN；默认不会跳过验证。常用端口为 UDP/TCP 514、TLS 6514，须按接收端实际配置填写。

支持 JSON、RFC 5424 Syslog（MSG 为 JSON）、自定义单行模板。Syslog 默认 local0/info，可配置 facility。模板可用 `{id}`、`{created_at}`、`{request_id}`、`{ip}`、`{method}`、`{path}`、`{action}`、`{rule_id}`、`{status}`、`{hostname}`、`{platform_name}`。双花括号 `{{`、`}}` 输出字面花括号；不支持 Python 表达式和格式化运算。字段中的换行及控制字符转义，避免产生伪造日志行。

示例：`{created_at} host={hostname} src={ip} method={method} path={path} action={action} rule={rule_id} status={status}`。

转发范围为 events 审计记录：正常访问、拦截、检测、旁挂观察、上游错误、管理配置操作。这里的“所有数据”指全部审计事件，不导出业务数据库、密码、Cookie、Authorization、请求体或控制台原始输出。

首次启用发送已有历史记录，然后发送新增事件。暂停会保留发送进度，重新启用继续；切换接收服务器也沿用进度，已发送历史不会自动重放。游标与配置存储在当前数据库，迁移数据库时同步迁移。发送在后台执行，失败约每 5 秒重试，可在页面查看待发送条数、最近发送时间和错误状态。

UDP 无接收确认，发送成功只代表交给本机网络栈。TCP/TLS 无应用层确认，进程中断可能重发；按 hostname 和 id 去重。该功能不承诺端到端可靠交付。尚未发送的事件依赖数据库保留，请勿手动删除。当前仅支持单接收端，每条消息最大 60000 字节。
