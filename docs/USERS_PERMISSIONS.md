# 用户、权限与密码管理

管理页面新增“用户管理”和“修改密码”。现有管理员首次升级时自动导入数据库，继续使用原账号密码，不需要重新创建。后续认证以数据库为准，不会因重启重新导入或恢复旧密码。

## 新增及编辑用户

有“用户管理”权限的用户进入对应菜单，填写用户名、角色、密码，保留“启用用户”，点击“保存用户”。用户名支持 1～64 位字母、数字及 `_.@-`，密码为 10～128 个字符。

点击列表“编辑”可修改角色、权限、启用状态及重置密码；用户名不可修改，编辑时密码留空保留原密码。删除需要确认；不能删除当前登录用户。系统至少保留一名启用的管理员，不能删除、停用或降级最后一名管理员。

停用后该用户的后续请求无法认证；变更权限对后续接口请求立即生效。已经打开的菜单可能需要刷新才能更新显示，但接口仍执行最新权限校验。

## 角色和权限

| 角色 | 默认权限 |
| --- | --- |
| 管理员 | 全部权限 |
| 运维人员 | 安全总览、站点与证书、防护规则 |
| 审计人员 | 安全总览、访问审计 |
| 自定义权限 | 逐项勾选需要的权限 |

自定义可分配安全总览、站点与证书、防护规则、访问审计、系统配置、用户管理六项。系统配置包含平台、数据库、日志、网卡和运行状态。权限按功能控制，当前不细分为只读/写入或按域名隔离。

固定角色的权限由系统预设，修改个别权限需选择“自定义权限”。无功能权限的有效用户仍可修改本人密码。授予“用户管理”意味着可以管理其他用户和权限，包含创建管理员，须作为高权限授权。

菜单按权限隐藏，后端 API 独立检查权限，直接调用未授权接口返回 403。规则权限可修改系统规则开关，但不能借用站点配置保存接口修改源站或其他站点参数。

## 修改本人密码及管理员密码

1. 登录需要修改密码的账号，进入“修改密码”。
2. 填写当前密码、新密码并再次确认。
3. 点击“修改密码”，旧密码立即失效，无需重启容器。

管理员修改本人密码采用同一流程。需要重置其他账号密码时，在“用户管理”编辑该用户并设置新密码，不要求旧密码。

当前页面在内存中使用新凭据继续请求，不将新密码保存在 localStorage 或数据库明文中。刷新页面或浏览器再次弹出 Basic 登录框时使用新密码。Basic 认证由浏览器缓存，关闭页面不一定清除浏览器凭据；共享终端应使用独立浏览器会话。

## 存储、备份与审计

用户记录保存到当前 SQLite / PostgreSQL 的 accounts 表，密码使用带随机盐的 PBKDF2-SHA256（600000 次）存储，不提供密码回显。数据库迁移及发布快照包含用户记录，数据库备份含敏感密码摘要，应限制访问。

用户新增、修改、删除和本人密码变更记录在“访问审计 → 配置变更”，对应 `USER_CREATE`、`USER_UPDATE`、`USER_DELETE`、`PASSWORD_CHANGE`。操作者写入事件来源字段，密码及摘要不会写入这些审计事件。

runtime/admin.env 中保留的原初始化凭据不再覆盖数据库密码。它用于初次导入及本机受限的健康检查，修改它不能重置已经导入的管理员。运行探针只在服务端确认连接来自 127.0.0.1、携带内部探针凭据且访问限定只读接口时生效，不可用于远程管理或用户管理。

忘记所有管理员密码时，应由服务器维护人员备份数据库后进行受控恢复；不要删除用户表或重新初始化数据库尝试恢复，以免丢失其他账号权限。
