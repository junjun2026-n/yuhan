# WAF 详细使用与运维说明

适用版本：2026 年 11 月当前项目版本。正式运行环境为 Ubuntu + Docker，Windows 用于本地开发。

### 多域名、多源站配置

复杂匹配可在站点配置点击「新增匹配规则」，分别填写域名、访问端口、路径前缀、优先级及多个源站。例如域名 `api.example.com`，端口 `443`，路径 `/v2`，优先级 `200`，源站每行填写 `http://10.0.0.21:8080`、`http://10.0.0.22:8080`。域名须列入受保护域名，支持完整域名或单层通配符。端口是访问 Host 中的端口，未显式带端口时 HTTP 为 80、HTTPS 为 443。端口留空表示任意端口。路径按解码后的请求路径做字符串前缀匹配，不改写路径。规则优先级数值越大越优先，同优先级精确域名优先，再按最长路径前缀，仍相同则按配置顺序。未匹配规则时回退至原域名源站池，再到默认源站。每条规则可关联多个后端，支持不同域名共享源站池，仍应用全部 WAF 检测和安全重试限制。修改或删除规则后点击「保存站点配置」生效。API 对应 `origin_rules` 数组。

在「站点配置」中每行填写一个受保护域名（支持 `*.example.org` 单层通配符），下方会自动生成对应的后端源站行及证书行。在某个域名的源站输入框中每行填写一个 HTTP / HTTPS 地址，最多 16 个，例如 `http://10.0.0.11:8080`、`http://10.0.0.12:8080`。点击「保存站点配置」立即生效；重新打开页面可查看已保存配置。删除受保护域名后，保存时会同时移除该域名的源站绑定。证书仍按域名单独选择。

反向代理模式下，不同域名转发至各自源站池，同域名在当前工作进程内轮询，精确域名优先匹配。未填写独立源站时使用默认源站；默认源站也为空则返回 503。未配置域名返回 403。GET / HEAD / OPTIONS 建立连接失败时尝试下一源站；其他方法、读取失败及 HTTP 错误响应不重试。全部连接失败返回 502。此功能不提供主动健康检查或会话粘滞，业务需要共享登录状态。原始 Host 会传给源站，HTTPS 后端证书必须可信。

该源站配置用于反向代理的 HTTP / HTTPS 入口；镜像旁挂和透明串联网桥不会按域名将连接重定向至源站池。

## 1. 系统用途与入口

管理页面提供用户名、密码登录。右上角「退出登录」撤销当前服务端会话并返回登录页；刷新、浏览器后退及其他已打开的控制台页面均不能继续使用已撤销的会话。重新登录需要再次输入密码。会话有效期为 8 小时，用户禁用、删除或密码更改后原会话立即失效；修改本人密码后返回登录页。管理登录使用 HttpOnly、SameSite Cookie；HTTPS 入口额外启用 Secure 属性。命令行 Basic 认证及内部健康探针仍保持兼容。会话表由系统自动创建，不迁移会话数据到新数据库。

系统提供 Web 请求防护、域名与 HTTPS 证书管理、IP 黑白名单、应急规则、访问审计及日志转发。支持反向代理、交换机镜像旁挂和双网卡透明串联。三种模式的接线和检测范围不同，应先确定流量经过哪个入口。

| 入口 | 默认地址 / 端口 | 用途 |
| --- | --- | --- |
| 管理页面 | `http://管理IP:8301` | 配置、查询和维护 |
| HTTP 业务入口 | `http://业务IP:8300` | 反向代理接入业务 |
| HTTPS 业务入口 | `https://受保护域名:8443` | 启用并加载证书后使用，可配置空闲的 443 |
| 本地开发管理 | `http://127.0.0.1:8401` | 独立开发数据及账号 |
| 本地开发业务 | `http://127.0.0.1:8400` | 本地验证代理 |

当前服务器管理地址为 `http://192.168.17.126:8301`，部署目录 `/opt/waf`。生产数据库为 `192.168.17.127:5432` 上的 `waf` 库。访问权限和网卡绑定以现场配置为准；页面能打开不等于业务数据平面已运行。

管理员账号默认为 `admin`，初始密码见服务器 `runtime/initial-admin.txt`，开发账号见本地 `runtime/dev/initial-admin.txt`。浏览器使用 HTTP Basic 登录框。本说明不包含实际密码。初始管理员自动导入数据库，后续在“修改密码”菜单修改本人密码，立即生效无需重启；旧初始密码文件不会自动变成新密码。用户管理及授权详见 [账号与权限说明](USERS_PERMISSIONS.md)。

### 2.1 安全总览统计与记录下钻

安全总览右上角“刷新数据”后方提供“大屏展示”，打开世界地图与公网 IP 访问连接图，并向整个页面请求浏览器全屏，隐藏浏览器标签栏、地址栏和工具栏，界面只保留大屏内容。右上角 × 或 Esc 退出。若浏览器策略限制自动全屏，会明确显示提示，可点击“进入浏览器全屏”重试或按 F11；网页无法越过浏览器的全屏限制，浏览器自身的退出提示仍由浏览器控制。

地图沿用总览选择的统计范围，可在全屏页切换全部、24 小时、7 天、30 天，并展示请求最多的 50、150 或 300 个公网 IP。每 15 秒自动刷新，可取消勾选或手动刷新；关闭后停止刷新。滚轮和加减按钮缩放，拖动平移，“复位”恢复位置。点击节点或右侧 IP 查看正向代理请求、拦截、观察和异常统计；具有访问审计权限的用户可跳转同一时间范围的来源记录。

公网来源按实际连接对端统计，不采信任意客户端提供的转发地址。定位使用现有 DB-IP Lite 离线国家归属及国家参考坐标，属于**国家级近似定位**，不是城市、街道或设备的真实坐标；同国家 IP 会分散排布以便选取。未知或缺少坐标的来源仅列在 IP 列表，不编造定位；内网和特殊用途地址不绘制。

WAF 图标是**逻辑汇聚点**，不表示服务器的地理位置。连线表示“公网来源 → WAF”的审计关系，粗细表示请求次数，节点和连线优先显示拦截红色、观察黄色、异常紫色、正常绿色。动态光点仅用于表达方向，不代表逐条实时数据包。当前审计未记录业务字节数，不能据此推算带宽或当前活跃 TCP 连接。顶部为所选范围全部公网请求，地图仅展示所选数量的高请求来源，并提示总 IP 数和未定位请求数。

底图和坐标已打包在项目内，页面无需调用外部地图服务，也不会上传访问者 IP。底图来自 Natural Earth（公共领域）；国家参考坐标来自 Google DSPL，遵循 BSD-3-Clause，许可证保存在 `waf/data/DSPL-LICENSE`。来源和校验值见 `waf/data/map-sources.json`。

- 总览提供域名、外部 IP、外部来源国家、黑名单、防护命中攻击类型、防护命中规则、访问路径、请求方法、响应状态码九类 TOP5，按记录数降序排列，同数按名称排序。
- 黑名单 TOP5 按命中 IP 排名，包括带来源 IP 条件的自定义拦截规则及业务端口来源黑名单；攻击 TOP5 按 SQL 注入、XSS、目录穿越、命令注入、扫描、CC、业务端口、自定义防护等类型排名，不重复包含黑名单命中。两者均包含拦截和观察命中，不含正常放行、管理操作或代理异常；防护命中表示风险线索，并不等于已确认攻击。
- 新记录保存命中时的类型，之后修改或删除规则不会改变已有统计。升级时按内置规则编号和当前自定义规则补齐旧记录；已删除或已变更的历史自定义规则无法完整还原，无法识别的自定义命中归为“自定义防护”。点击排名项可进入同一时间范围的审计列表。
- 统计范围可选全部留存记录、最近 24 小时、7 天、30 天，汇总数字与排名使用同一范围；管理配置操作不计入。计数按业务审计记录计算，旁挂或串联中同一请求的多条命中可能形成多条记录。
- 点击请求总数、已拦截、观察命中、已转发、旁挂已审计、代理异常数字，或排名项，进入“访问审计”列表，自动带上对应条件、时间范围及统计截止时间。支持原有分页和每页条数；“清除总览筛选”恢复全部记录。快照截止后的新请求不进入该列表，需要回到总览刷新后重新查看。
- 明细须具备“访问审计”权限。只有总览权限的用户可看汇总，不能打开明细，服务器接口也保留权限校验。
- 外部 IP 指真实连接来源中可公网路由的 IPv4 / IPv6，排除内网、回环、共享地址及多播等特殊地址。当前不信任客户端提供的 X-Forwarded-For，若前面有代理，统计会显示该代理的连接 IP。
- 国家使用内置 DB-IP Lite 离线数据库，查询不向外部发送访客 IP。国家是地址登记归属，不代表访客物理位置；未知记为“未知国家 / 地区”。该数据基于 CC BY 4.0，来源：[IP Geolocation by DB-IP](https://db-ip.com)。维护人员可执行 `python -m tools.update_geoip` 更新本地索引后重新部署服务。
- 升级会新增审计字段并补齐历史记录可识别的来源国家；历史日志没有保存域名，不能推测补录，统一显示“未记录”，不计入域名 TOP5。升级后的反向代理、CC/端口拦截和明文 HTTP 旁挂/串联记录开始保存合法的 Host 域名。未解密 HTTPS、无效 Host 等仍可能没有域名。

## 3. 首次部署与管理网卡初始化

### 3.1 Ubuntu 启动

准备 Ubuntu Server、Docker Engine 和 Compose v2，复制项目至 `/opt/waf`。全新安装不要复制开发环境的 `.env`、虚拟环境和开发 runtime。正式部署完整步骤见 [Ubuntu Docker 部署](UBUNTU_DOCKER.md)。

```bash
cd /opt/waf
ip -br link
# 根据实际网卡编辑 mgrnic.ini 后启动
bash start.sh
docker compose ps
docker compose logs --tail=100 waf
```

### 3.2 mgrnic.ini 示例

以下接口名仅为示例，必须替换成现场专用网卡；管理 IP 必须确认无冲突。

```ini
[management]
alias = mgmt0
interface = enp1s0
physical_id =
mac =
ip = 192.168.1.1/24
nic_count = 3
apply_ip = true

[business:port1]
interface = enp2s0
bring_up = true

[business:port2]
interface = enp3s0
bring_up = true
```

- `alias` 是系统逻辑名称，用于将配置与具体硬件分开。
- 每个网卡的 `interface`、`physical_id`、`mac` 三种选择方式只填写一种。全部留空不会自动挑选硬件。
- `nic_count` 包含一个管理口，范围为 1～32；其余为业务口。
- `apply_ip=true` 添加管理地址，不删除原地址，不修改默认网关。因此同一管理网卡可能同时显示原地址和新增管理地址。
- 管理配置首次导入完成后由数据库保存，后续调整在页面进行，修改 INI 不会覆盖已完成的管理初始化。
- 业务口加载有独立初始化记录；更换硬件时优先在页面将原别名重新绑定新物理网卡，详细规则见 [管理口与业务口加载](MGRNIC_DOCKER.md)。

Docker 使用宿主机网络和 NET_ADMIN / NET_RAW 权限。网卡操作作用于 Ubuntu 宿主机，无需创建同名容器虚拟网卡。管理口不能作为业务桥接口。部署时管理服务监听 `0.0.0.0:8301`，业务代理监听 `0.0.0.0:8300`；浏览器使用服务器实际 IP 访问 `http://服务器IP:8301/login`。管理 IP 应用后无需重新创建监听进程。本地独立开发环境保持 `127.0.0.1:8401` 和 `127.0.0.1:8400`。

## 4. 三种接入模式

| 模式 | 接入方式 | 能否阻断 | HTTPS 内容 |
| --- | --- | --- | --- |
| 反向代理 | 客户端 → WAF 8300 / HTTPS 入口 → 源站 | 可按策略拦截 | WAF 加载域名证书并终止 TLS 后检测 |
| 镜像旁挂 | 交换机镜像目的口 → 独立业务网卡 | 只能审计 | 不解密第三方 HTTPS |
| 透明串联 | 上游 → 业务口 1 → 软件桥 → 业务口 2 → 下游 | 可丢弃命中报文 | 不解密第三方 HTTPS |

在“系统配置 → 网卡配置”选择模式和网卡别名并保存。旁挂必须配置镜像口，串联必须配置不同的进、出口。业务口不得有主机 IPv4 / 全局 IPv6 地址，也不能已加入其他 bridge / bond。宿主机网络服务不能重新接管这些业务口。

旁挂与串联目前检测 TCP 80、8080 的明文 HTTP/1.x。不要把反向代理的 HTTPS 卸载能力理解为串联对加密流量的解密能力。串联属于软件桥，停止服务可能中断链路，没有硬件断电直通能力。上线前在维护窗口验证接线、正常流量、命中拦截和恢复流程。

保存后到“运行状态”确认数据平面状态、绑定和错误。未绑定业务口、启动失败或 Docker unhealthy 时，不能认为旁挂或串联已生效。当前主机若只有管理网卡，需先补充专用业务网卡才能使用对应模式。

## 5. 站点配置

进入“站点配置 → 站点配置”。

1. 在“受保护域名”中每行填写一个域名，如 `www.example.com`。`*.example.org` 只匹配单层子域，不包含根域名及多层子域。
2. 填写源站地址，如 `http://192.168.17.128:8080`。只填写协议、主机及端口，不含路径。不要填写 WAF 自身业务入口，否则可能形成循环。
3. 首次接入选择“观察”模式，设置每 IP 每分钟请求数和最大请求体。
4. 根据业务需要启用攻击特征检测，点击“保存站点配置”。
5. 将业务 DNS、端口转发或上级入口指向 WAF，验证正常访问和访问审计，再切换“拦截”模式。

域名留空时兼容任意 Host；填写后，未配置域名和直接 IP 业务访问会被拒绝。配置域名后测试业务应携带正确 Host，例如：

```bash
curl -i --resolve www.example.com:8300:192.168.17.126 http://www.example.com:8300/
```

所有受保护域名共用一个源站和站点策略，当前不支持按域名分别配置源站。源站使用 HTTPS 时会校验证书。建议限制源站只接受 WAF 转发，避免用户绕过防护入口。

关闭攻击特征检测不会关闭域名、方法、限流及请求大小限制，也不会停用自定义紧急拦截。前置其他代理时，来源识别及限流按连接对端 IP 进行，不能通过伪造 X-Forwarded-For 获取可信来源身份。

## 6. HTTPS 证书库与证书加载

### 6.1 上传证书

1. 先在“站点配置”页签填写受保护域名，再切换“HTTPS 证书库”。未保存的域名草稿也会同步到域名下拉框。
2. 选择“证书对应域名”，或者选择“仅上传到证书库，暂不绑定域名”。
3. 选择证书文件，系统按内容识别 PEM、DER、PKCS#7（P7B/P7C）、PKCS#12（PFX/P12）。
4. PFX/P12 或包含私钥的合并 PEM 可不另选私钥；其他证书通常需要匹配的 PEM / DER 私钥。
5. 如文件加密，填写证书 / 私钥密码，可勾选显示。点击“上传证书到证书库”。证书最大 1 MiB，独立私钥最大 64 KiB。

系统检查证书有效期、域名 SAN、私钥匹配和证书链。上传成功会清空导入密码。切换回站点页签会隐藏密码显示，但保留未提交的导入草稿和所选文件；刷新页面会清空文件选择。

### 6.2 加载与验证

1. 返回“站点配置”页签，在“证书加载”中为每个域名选择有效且匹配的证书。上传时选择了域名，会回填相应绑定草稿。
2. 勾选“启用 HTTPS 防护入口”，设置端口，点击“保存站点配置”。单独上传证书不会改变运行中的绑定。
3. 在证书库页签点击“刷新 HTTPS 状态”，确认入口运行中。
4. 使用正确域名访问并检查证书。例如：

```bash
curl -I --resolve www.example.com:8443:192.168.17.126 https://www.example.com:8443/
```

客户端需信任签发 CA。精确域名的证书优先于通配符，未知 SNI 拒绝握手。未发送 SNI 的旧客户端使用第一个受保护域名证书，HTTP Host 仍需通过检查。

续期时上传新证书，为相关域名选择新证书并保存，再验证有效期。系统不自动申请或续期。证书及私钥位于服务器 `runtime/tls/`，须单独备份；只备份数据库不能恢复私钥。HTTPS 入口重载可能使现有连接短暂中断，管理页面 8301 不会因此自动变为 HTTPS。

## 7. 防护规则

### 7.1 系统防护规则页签

内置 SQL 注入、XSS、目录穿越、命令注入、敏感文件扫描等基础特征规则。按业务开关对应规则后点击“保存规则配置”。观察模式记录命中但继续转发，拦截模式对命中返回 403。更改后通过正常业务及受控测试验证误报情况。

### 7.2 自定义规则页签

支持新增、编辑、停用、启用、删除，提供“拉黑 IP”“加白 IP”“紧急防护”快捷入口。快捷按钮只预填表单，仍需保存才能生效。最多 200 条规则。

| 字段 | 填写说明 |
| --- | --- |
| 规则名称 | 便于识别的名称 |
| 处理动作 | 拦截 / 黑名单、放行 / 白名单、仅记录命中 |
| 优先级 | 1～10000，数字小先执行；相同优先级按规则编号排序 |
| 来源 IP / 网段 | IPv4、IPv6 或 CIDR，例如 `203.0.113.0/24` |
| 匹配域名 | 完整域名或单层通配符 |
| 请求方法 | 逗号分隔，如 `GET,POST`；空为全部 |
| URL 路径 | 支持前缀、精确、包含 |
| URL 关键字 | 检查路径与查询参数，不检查请求体或头部 |
| 自动到期时间 | 按浏览器本地时间填写，空为长期有效 |
| 匹配全部请求 | 允许建立无其他条件的全站规则；已填条件仍参与匹配 |

多个条件使用 AND，全部满足才命中。至少填写一个条件或明确选择匹配全部请求。规则按顺序首条匹配生效：白名单可能被更高优先级的黑名单先命中，反之亦然。

- 拦截：反向代理返回 403，即使系统特征检测关闭或处于观察模式也执行。
- 放行：跳过基础攻击特征及后续自定义规则，域名、限流、方法和大小限制仍执行。
- 仅记录：继续系统特征检测，因此仍可能被系统规则拦截。

示例：临时关闭某域名管理接口，设置动作为拦截、优先级 1、域名 `www.example.com`、路径 `/admin` 前缀、适当到期时间，然后保存。审计中按 `CUSTOM-…` 编号关联规则。到期即时停止匹配，记录仍保留，可延长时间。管理入口不受业务自定义规则限制。

镜像旁挂只能记录命中，不能执行实际阻断。详情见 [自定义规则说明](CUSTOM_RULES.md)。

## 8. 访问审计与分页

CC 防护与业务端口防护位于“防护规则 → 自定义规则”，每类最多支持 100 条策略，可分别新增、编辑、启停、删除，并独立绑定域名或目标 IP。CC 可设置统计窗口、请求阈值和临时封禁；业务端口策略还可选择 HTTP/HTTPS、指定监听端口，设置来源黑白名单和并发限制。多个策略匹配时必须全部通过。旧配置自动保留。仅作用于反向代理 HTTP/HTTPS 业务入口，管理入口不受影响。详见 [CC 与业务端口防护](TRAFFIC_PROTECTION.md)。

访问审计记录时间、来源 IP、请求方法与路径、处理结果、命中规则、状态码及请求编号。时间按浏览器本地时区显示。查询参数、请求体、Cookie、认证头不写入事件明细。

| 筛选项 | 含义 |
| --- | --- |
| 全部结果 | 全部访问与配置变更事件 |
| 已拦截 | 被防护规则或限制阻止 |
| 观察命中 | 观察模式或仅审计场景发现命中，不能单凭此项判断已阻断 |
| 已转发 | WAF 已转发的请求，业务是否成功还需看状态码和源站 |
| 旁挂已审计 | 镜像采集的普通流量审计 |
| 代理异常 | 源站连接、超时或代理处理异常 |
| 配置变更 | 管理配置操作及相关管理审计 |

底部“每页显示”可选 20、50、100、200、500 条，默认 100。页面显示“共 N 条 · 第 X / Y 页”，总页数按当前筛选结果向上取整计算。例如 105 条、每页 50 条，共 3 页。无记录时显示 0 / 0 页。

切换筛选条件或每页条数会返回第一页；第一页禁用“上一页”，末页禁用“下一页”。顶部“刷新数据”会重新读取记录及总数；当前不提供自动定时刷新。新事件进入后总数可能变化，查询结果按最新事件优先排序，不是固定时点快照。

排查时先按结果筛选，再核对时间、来源、路径和规则编号。业务请求响应中的 `X-WAF-Request-ID` 可与审计的请求编号关联。审计当前没有全文搜索、批量导出、自动清理或归档按钮。

## 9. 系统配置六个页签

### 9.1 平台配置

平台名称保存后更新侧栏、浏览器标题及页脚。设备主机名是容器主机名，不修改 Ubuntu 宿主机名。主机名保存后在服务器 `/opt/waf` 执行 `bash start.sh` 重建容器应用，单独 restart 不能变更主机名。

### 9.2 数据库配置

下拉选择 SQLite 或 PostgreSQL（PQ）。SQLite 填写持久化文件路径；PQ 填写服务器、端口、库名、用户、密码和 TLS 模式。建议使用 WAF 专用数据库与账号。

连接字段随数据库类型切换：选择 PQ 时隐藏并禁用 SQLite 文件字段，选择 SQLite 时隐藏并禁用 PQ 连接字段。页面状态显示实际运行连接、当前访问地址和待生效状态；待生效配置不代表已经切换数据库。本地独立开发入口 8401 使用 SQLite，服务器部署入口 8301 使用服务器已配置的存储，两者不共享开发配置。

已通过连接测试并保存的配置按类型保留，切换回 PQ 时可自动带出已保存的主机、端口、数据库名和用户名，密码留空可保留相同连接的已保存密码。首次配置且没有已保存连接时，必须填写 PQ 主机、数据库名、用户名及密码；这些输入框中的灰色示例文字不是实际配置。

1. 填写连接，点击“测试所选连接”。
2. 新库可点击“数据初始化”，创建缺失的表、索引和默认配置，已有记录保留，可重复执行。PostgreSQL 数据库本身必须预先创建，账号须有建表及读写权限。
3. 点击“保存数据库配置”后为待生效状态，当前服务仍使用原库。初始化不会复制历史数据，也不会自动启用新连接。
4. 要保留历史配置与审计，先备份、停止写入，再迁移并切换：

```bash
cd /opt/waf
docker compose stop waf
docker compose run --rm --no-deps --entrypoint python waf -m waf.switch_database
docker compose up -d --no-build --pull never waf
```

迁移校验记录及内容后才启用新连接，目标已有业务数据会拒绝覆盖。源库保留，但切换后的新增数据不会回写旧库，不能把切回旧库当成无损回滚。

“显示密码（含已保存密码）”支持查看同一连接的已保存密码，会产生 `DATABASE_PASSWORD_VIEW` 审计，密码内容不写入事件。普通配置查询不返回密码。切换功能页签会收起显示。连接配置在服务器 `runtime/database.env`，待生效配置为 `runtime/database.pending.env`。

SQLite 的 WAL 检查点配置不适用于 PQ；PQ 使用连接等待参数作为 SQL 执行超时。数据库不可用时不会静默回退到 SQLite。详情见 [数据库与平台配置](SYSTEM_CONFIGURATION.md)。

### 9.3 日志配置

填写接收服务器 IP、端口、协议和格式，点击“发送测试日志”，先在接收端确认，再启用并保存。测试使用当前表单草稿，不会自动保存配置。

支持 UDP、TCP、TCP + TLS；常用端口 514、TLS 6514，按接收端实际配置填写。TLS 校验证书信任链及 IP SAN。TCP / TLS 使用 LF 换行分帧。

格式可选 JSON、RFC 5424 Syslog（消息为 JSON）、自定义模板。自定义示例：

```text
{created_at} host={hostname} src={ip} method={method} path={path} action={action} rule={rule_id} status={status}
```

可用字段还包括 `{id}`、`{request_id}`、`{platform_name}`。`{{` 和 `}}` 输出字面花括号，不支持 Python 表达式。

首次启用先发送历史事件，再发送新事件。暂停后保留进度，换接收服务器不自动重放已发送历史。查看待发送条数、最近发送和错误状态；失败约每 5 秒重试。UDP 发送成功不代表接收成功；TCP / TLS 也无应用层确认，重启时可能重发，建议接收端按 hostname 与 id 去重。

转发的是全部审计事件，不是数据库导出、私钥、密码或业务请求体。不要删除未发送事件。详见 [日志转发说明](LOG_FORWARDING.md)。

### 9.4 网卡配置

手动设置逻辑网卡数量、一个管理口、业务别名及物理绑定，选择接入模式和对应业务口。更换硬件后保留逻辑别名，重新绑定实际物理网卡并保存。管理 IP 添加行为可能保留原 IP，因此两条地址并不表示两个管理口。

串联配置会操作宿主机软件桥，变更接线或端口前先安排维护窗口。保存后核对运行状态，不能只以保存成功判断接线和检测成功。

### 9.5 运行状态

检查管理 IP、网卡绑定、初始化记录、数据平面进程及错误信息。旁挂 / 串联配置不完整会使数据平面停用，即使管理页面和反向代理仍可用。Docker unhealthy 不会由 Docker 自身自动触发重启。

### 9.6 部署说明

提供部署提示及本使用说明下载入口。首次上线、换网卡、切换数据库、证书续期和故障恢复前，应阅读相应专题文档。

## 11. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 8300 不能打开管理页面 | 8300 是业务入口，管理使用 8301；同时检查监听地址、路由及防火墙 |
| 业务返回 503 | 未配置源站时属预期，保存可达的源站地址 |
| 业务返回 502 | 检查源站端口、连接、超时和 HTTPS 源站证书 |
| 域名配置后 IP 访问被拒绝 | 使用受保护域名访问，或在受控测试中指定正确 Host |
| 正常请求被 403 拦截 | 查访问审计中的规则编号，区分 DOMAIN、自定义和系统规则，再调整对应条件 |
| 返回 429 / 413 | 分别检查每 IP 限流与请求体大小；白名单不绕过这些限制 |
| 证书域名下拉为空 | 先在站点配置页签填写受保护域名，再进入证书库 |
| 证书上传成功但入口未启用 | 返回站点配置确认绑定、启用 HTTPS 并保存，然后刷新 HTTPS 状态 |
| 证书无法加载 | 核对 SAN、有效期、匹配私钥、解密密码和监听端口冲突 |
| 数据库保存后仍显示旧库 | 新连接处于待生效，按停服迁移流程切换 |
| 新数据库初始化失败 | 检查网络、账号权限；PQ 数据库本身须先存在 |
| 日志测试成功但接收端没有数据 | UDP 无交付确认，检查服务器监听协议、端口、防火墙及格式 |
| 旁挂没有记录 | 确认交换机镜像、专用业务口绑定及进程状态，使用支持的明文 HTTP 流量验证 |
| Docker unhealthy 但页面可访问 | 检查数据平面错误、业务口绑定及启动状态，管理可用不能代表数据平面运行 |
| 页面显示旧样式 | 使用 Ctrl+F5 强制刷新，核对正在访问的管理地址 |

## 12. 当前能力边界

该项目采用基础特征检测与自定义匹配，可能误报或漏报，上线前应结合实际业务验证。当前为单源站、单代理 worker 的设计；限流在单进程内存中，重启会清空，不是分布式限流。

当前不提供多租户、多源站路由、可信代理链、WebSocket、SSE 或完整 JSON / multipart 语义检测。请求体可配置到 10 MiB，响应缓冲上限 20 MiB，不适合大文件下载和长连接。不能直接承诺特定用户数或吞吐量，须按真实请求大小、规则、TLS、数据库延迟及硬件压测。

反向代理 HTTPS 防护、镜像旁挂与透明串联的能力应分别验收。浏览器能打开页面、配置保存成功和 Docker 容器运行，都不能单独替代业务防护效果验证。
