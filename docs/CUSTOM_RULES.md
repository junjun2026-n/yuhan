# 自定义防护、紧急拦截与黑白名单

进入“防护规则 → 自定义规则”页签，在“自定义防护 / 黑白名单”中新增规则。系统内置规则位于独立的“系统防护规则”页签。提供“拉黑 IP”“加白 IP”“紧急防护”快捷入口，填写后保存立即生效。支持编辑、停用、重新启用和删除，最多 200 条，SQLite 和 PostgreSQL 均可保存并随数据库迁移。

规则可组合：来源 IPv4/IPv6 或 CIDR 网段、精确/单层通配域名、请求方法、URL 路径（前缀/精确/包含）、URL 关键字（路径与查询参数）。多个条件使用 AND，同时满足才命中；留空不参与匹配。路径和关键字按两次 URL 解码后的内容比较，可选区分大小写。不匹配请求体、Cookie、认证头或响应。来源 IP 使用连接对端地址，不信任请求中的 X-Forwarded-For。

至少填写一个条件，或者明确勾选“匹配全部请求”。该勾选仅允许条件为空；若填写了其他条件，这些条件仍须同时满足。优先级 1～10000，数字小的先执行；相同优先级按规则编号排序。自定义规则首条匹配生效。因此，优先级更高的黑名单会优先于白名单，反之亦然。

- **拦截 / 黑名单**：返回 HTTP 403；即使基础攻击检测关闭或处于观察模式，也执行拦截。适用于封禁恶意 IP/网段、临时关闭敏感路径或拦截应急利用 URL。
- **放行 / 白名单**：跳过本次请求的基础 SQL 注入、XSS 等攻击特征检测和后续较低优先级自定义规则。既有受保护域名、请求大小、限流与方法限制仍生效，源站错误也照常返回。
- **仅记录命中**：不会因该自定义规则拦截，继续原有基础检测；基础检测仍可能拦截请求。

自动到期时间按浏览器本地时区填写，存储为 UTC。到期后立即停止匹配，无需定时任务；规则保留在列表并显示“已到期”，可编辑延长。留空长期有效。停用后立即停止匹配。

示例：

| 用途 | 动作 | 优先级 | 条件 |
| --- | --- | --- | --- |
| 紧急关闭管理接口 | 拦截 | 1 | 域名 `www.example.com`，路径 `/admin` 前缀 |
| 恶意来源网段 | 拦截 | 10 | 来源 IP `203.0.113.0/24` |
| 内部测试来源 | 放行 | 20 | 来源 IP `192.168.1.10`，域名 `test.example.com` |
| 观察特定 URL | 仅记录 | 100 | URL 关键字 `probe-token` |

命中写入“访问审计”，规则编号为 `CUSTOM-…`，与列表中的编号对应。命中事件也通过已启用的日志转发发送到日志服务器。创建、编辑和删除配置同样产生管理审计。

反向代理 HTTP/HTTPS 和透明串联明文 HTTP 使用相同匹配条件。透明串联以流式检查执行，紧急拦截会丢弃后续匹配报文；镜像旁挂仅将黑名单命中记为“检测”，不会阻断链路。TLS 卸载后的 HTTP 由反向代理检查；旁挂和透明串联不解密第三方 HTTPS。实际业务采集仍依赖已绑定并运行的数据平面网卡。

规则存储在主配置中独立维护；保存站点配置或基础规则开关会保留最新自定义规则，避免旧页面覆盖新规则。管理入口使用单独服务，不受业务防护规则影响。
