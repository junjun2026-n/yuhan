# yuhan Web 应用防火墙

支持配置独立蜜罐地址，将代理入口命中的攻击请求转送蜜罐并保留拦截审计，详见[蜜罐配置](docs/HONEYPOT.md)。

版本：**v0.261115** · 请遵守版权协议 · [GPLv3 完整许可](LICENSE) · [版权说明](COPYRIGHT.md)

项目名称与目录：`yuhan`。GitHub 仓库：[junjun2026-n/yuhan](https://github.com/junjun2026-n/yuhan)。

Python 模块名仍为 `waf`，下方启动命令按该模块名执行。

安全总览支持九类 TOP5（含黑名单来源 IP、攻击类型）、时间范围筛选，以及点击汇总数字/排名项打开审计列表。国家归属使用内置 DB-IP Lite 离线索引，支持 IPv4/IPv6；历史域名缺失显示“未记录”。详见使用手册“安全总览统计与记录下钻”。

总览“刷新数据”右侧新增“大屏展示”：离线世界地图、公网 IP 国家级近似定位、请求连线、缩放拖动、来源详情、15 秒自动刷新及审计跳转。线宽按请求次数显示，WAF 为逻辑汇聚节点；不表示真实地理链路、流量字节数或实时活跃连接。地图与坐标来源、许可和校验值见 `waf/data/map-sources.json`。

完整操作手册：[WAF 详细使用与运维说明](docs/USER_GUIDE.md)，涵盖部署初始化、全部菜单与页签、HTTPS、规则、审计分页、数据库、日志、备份及故障排查。管理页面“系统配置 → 部署说明”提供下载入口。新增 [用户、权限及密码管理](docs/USERS_PERMISSIONS.md)：支持管理员、运维、审计及自定义权限，账号持久化到数据库。

正式部署采用 **Ubuntu + Docker**，镜像基于 Ubuntu 24.04，使用 Compose 启动服务。
新增应用＋PostgreSQL 一键启动：`bash start-stack.sh`，使用 `compose.stack.yaml`，详见 [Compose 应用与数据库启动](docs/COMPOSE_STACK.md)。当前外部数据库部署仍使用原启动方式。
FastAPI / HTTPX 提供管理与代理，支持 SQLite / PostgreSQL 持久化全部配置和审计；镜像旁挂与透明串联由容器内 Linux 数据平面处理。数据库选择、迁移与备份参见 [系统配置说明](docs/SYSTEM_CONFIGURATION.md)。

反向代理支持域名白名单（完整域名、单层通配符），自动识别 PEM、DER、PKCS#7、PFX/P12 证书，按域名绑定并加载 HTTPS 入口。默认 HTTPS 端口为 8443，可配置为未占用的 443。配置步骤与检测范围参见 [HTTPS 与域名防护说明](docs/HTTPS_DOMAINS.md)。

部署入口：先填写 `mgrnic.ini` 的实际管理网卡，再在 Ubuntu 项目目录执行 `bash start.sh`。
详细安装、接线、权限、持久化和维护说明见 [Ubuntu Docker 部署文档](docs/UBUNTU_DOCKER.md)。

## 首次初始化配置 mgrnic.ini

项目根目录的 `mgrnic.ini` 用于首次指定管理网卡和管理 IP。首次运行前填写：

文件还支持 `[business:port1]`、`[business:port2]` 配置 Docker 业务网卡加载，与管理口一样可按接口名、物理标识或 MAC 绑定。详见 [管理口与业务口加载](docs/MGRNIC_DOCKER.md)。

```ini
[management]
alias = mgmt0
interface = 以太网
physical_id =
mac =
ip = 192.168.1.1/24
nic_count = 3
apply_ip = true
```

- `alias`：系统逻辑管理网卡别名，默认 `mgmt0`。
- `interface`：系统网卡实际名称，精确匹配；Windows 如 `以太网`，Linux 如 `enp1s0`。
- `physical_id`：也可以填写系统枚举出的稳定物理标识，替代 `interface`。
- `mac`：也可以使用 MAC 地址，支持 `AA:BB:CC:DD:EE:FF` 和 `AA-BB-CC-DD-EE-FF`。
- `interface`、`physical_id`、`mac` **只填一项**。模板全部留空，不自动选择或修改当前主机的任何网卡。
- `ip`：管理 IPv4 / 前缀，默认 `192.168.1.1/24`。
- `nic_count`：逻辑网卡总数量，含一个管理口，范围 1～32；其余创建为业务口。
- `apply_ip`：`true` 导入配置并添加管理 IP；`false` 仅导入配置，稍后通过系统配置页面应用 IP。

文件使用 UTF-8 编码（支持 BOM），不包含管理员账号密码，不支持网关配置，不会改动默认路由。
只填写专用管理网卡，默认附加管理 IP，不删除网卡已有 IP。

运行 `.venv\Scripts\python.exe -m waf.cli init` 或启动 `start.ps1` 会自动执行此初始化。
`apply_ip=true` 时需要使用管理员 PowerShell / Linux root 运行；Windows DHCP 网卡仍会被拒绝应用，以保护现有网络。
Linux 示例把 `interface` 改成实际名称，执行 `.venv/bin/python -m waf.cli init`。

也可独立检查并重试网卡初始化：

```powershell
.\.venv\Scripts\python.exe -m waf.cli init-network
```

仅该命令在等待填写网卡、匹配失败、格式错误或 IP 应用失败时返回非零退出码。
正常服务启动遇到这些情况仍会在 `0.0.0.0:8301` 提供管理入口，不会声称网卡初始化成功。
在「系统配置 → 运行状态与管理 IP」查看初始化状态和错误原因。
INI 导入成功但 IP 应用失败时，配置会保留为待应用状态；修正配置或权限后再次启动自动重试。
如果管理 IP 已存在于对应网卡，则不会重复添加。

初始化完成后（包括 `apply_ip=false` 的仅导入模式），文件不再覆盖数据库配置。
以后网卡绑定和 IP 由页面管理；如果初始化选择了自动应用 IP，后续启动会从**数据库中保存的配置**恢复缺失的管理 IP，
用于 Linux 重启后地址恢复，不再重新导入 INI。
已存在自定义网卡配置，或初始化未完成期间有人在页面修改配置时，会跳过 INI 导入，保护已有配置。
更换硬件应在页面重新绑定原别名，不能依靠修改已经完成初始化的 INI 强行覆盖。
初始化记录保存在当前使用的数据库中，不使用配置文件删除或文件重命名作为成功标志。

## 接入站点

1. 登录管理控制台，在「站点配置」填写源站，如 `http://127.0.0.1:8000`。不要填 WAF 的 8300 / 8301 端口。
2. 建议先选「观察」模式，验证正常业务与「访问审计」，再切换「拦截」。保存立即生效。
3. 使用 `http://服务器IP:8300` 访问业务。默认未配置源站时返回 503，这是待配置状态。
4. 在前置代理配置域名与 TLS，将流量转发到 8300，并用防火墙限制源站只接受 WAF 访问，避免绕过防护。
5. 管理页面只在服务器本机浏览器访问；如需远程管理，使用 SSH 隧道或受限管理网络配合 HTTPS，不应直接暴露管理端口。

## 已实现功能

- [CC 与 HTTP/HTTPS 业务端口防护](docs/TRAFFIC_PROTECTION.md)：按来源 IP 统计窗口与临时封禁、来源黑白名单、HTTP 并发限制。默认关闭，在“防护规则 → 自定义规则”配置，管理入口不受影响。

- 单源站 HTTP / HTTPS 反向代理；HTTPS 源站验证证书，不跟随重定向。
- SQL 注入、XSS、目录穿越、命令注入、敏感文件扫描基础特征检测；支持两层 URL 解码和 HTML 实体解码。
- 拦截 / 观察模式、单规则启停、按客户端 IP 限速、请求体大小限制。
- 安全总览、中文站点配置、防护规则、分页审计查询。
- 请求关联编号 `X-WAF-Request-ID`，拦截 403、限速 429、超大请求 413、源站异常 502。
- 不信任客户端的 Forwarded / X-Forwarded-*，转发时重新设置来源地址；客户端不能指定转发源站。
- 审计记录时间、来源 IP、方法、路径（最多 512 字符）、结果、规则与状态码。
  不保存查询参数、请求体、Cookie、认证头和命中内容。应用应避免将密码等敏感信息放在 URL 路径。

特征检测开关仅控制攻击特征规则，关闭后限速、请求体大小和方法限制仍生效。
前置反向代理场景下限速按代理 IP 计数，当前版本尚未实现可信代理链配置。

## 当前范围

这是可运行的基础版本，特征规则可能误报或被绕过，不能替代成熟 WAF 引擎、安全开发和业务权限校验。
尚不包含多租户、多源站路由、分布式限速、WebSocket、SSE 或完整 multipart / JSON 语义解析。支持 HTTPS 证书库及按域名加载证书，所有域名共用一个源站。
请求体默认最大 1 MiB（可配置到 10 MiB），响应缓冲最大 20 MiB，不适合大文件或长连接服务。
限速为单进程内存固定窗口，重启会清空；应保持代理单 worker。
生产部署需根据实际业务完成规则调优、压力测试、高可用、告警与日志生命周期管理。

## 系统配置：网卡别名和管理口

管理菜单新增「系统配置」。网卡数量可手工设为 1～32，默认 3 个逻辑网卡：

| 别名 | 用途 | 默认地址 |
| --- | --- | --- |
| `mgmt0` | 唯一管理口 | `192.168.1.1/24` |
| `port1` | 业务口，可作镜像口或串联入口 | 不分配业务 IP |
| `port2` | 业务口，可作串联出口 | 不分配业务 IP |

别名可以修改为其他小写英文名，允许数字、下划线、连字符。硬件标识与别名分别保存；
Windows 按 InterfaceGuid 绑定，Linux 按永久 MAC（不可用时按当前 MAC）绑定。
操作系统重命名网卡不会改变逻辑引用。更换硬件后需在页面将原别名绑定到新网卡，业务角色和管理 IP 保持不变；不会自动猜测新硬件对应哪一个端口。
网卡缺失会显示「绑定丢失」，不会自动绑定其他网卡。同一物理网卡不能重复使用。

使用步骤：

1. 设置网卡数量并点击「更新网卡数量」，填写别名，指定且仅指定一个管理口。
2. 逐行选择实际网卡，按用途选择镜像口或串联入口 / 出口，保存。
3. 为管理口配置所需地址，确认网段和地址没有冲突后点击「应用已保存的管理 IP」。
4. 应用需要管理员 / root 权限；当前 Windows 进程没有管理员权限时按钮禁用。
5. IP 为附加地址，不删除已有地址，不修改网关；Windows 的 DHCP 网卡会被拒绝操作，以免 New-NetIPAddress 自动关闭 DHCP。请使用专用静态管理网卡。
6. 部署服务统一监听 `0.0.0.0:8301`，可通过服务器现有 IP 或已应用的管理 IP 访问，无需为每个 IP 启动独立管理进程。
   默认管理地址对应 <http://192.168.1.1:8301>。需管理端客户端同网段，检查系统防火墙；远程管理建议使用受限管理网和 HTTPS 前置代理。

仅「保存」不会给主机添加 IP。初始默认地址是一项待应用配置，并不表示当前电脑已经使用此地址。
为了保留当前主机连接，本次安装没有自动选择物理网卡，也没有修改主机网络。
保存不同的系统配置会使运行中的 Linux 数据平面退出，串联桥接会拆除，请在维护窗口变更并重新启动。

## 旁挂 / 串联数据平面（Linux，直接 Python 调试）

正式 Docker 部署会自动启动数据平面，不需要执行本节的 Python 启动命令。以下步骤用于不使用 Docker 的 Linux 开发调试。

旁挂指交换机镜像采集，串联指双业务网卡软件透明桥接。与 HTTP 反向代理的「观察 / 拦截」规则模式分开配置。
Windows 可编辑部署规划、管理网卡绑定和 IP；当前不提供 Windows 镜像驱动和透明桥接驱动。
数据平面模块已提供，尚未在实际 Linux 网卡、交换机镜像口或桥接链路上验收。

Linux（示例 Debian / Ubuntu）需 root、iproute2、nftables、libpcap 和 NFQUEUE：

```bash
sudo apt-get install python3-venv python3-dev build-essential iproute2 nftables libpcap0.8 libnetfilter-queue-dev
cd /opt/waf  # 将项目复制到 Linux，不复制 Windows 的 .venv
python3 -m venv .venv
.venv/bin/pip install -r requirements-linux.txt
.venv/bin/python -m waf.cli init
.venv/bin/python -m waf.cli serve
```

先在 Linux 本机管理页面绑定实际网卡，保存部署模式和管理 IP。
使用专用业务口，移除业务口上的主机 IPv4 / 全局 IPv6 地址，并停止系统网络服务对这些口的自动配置。
不要把 SSH 远程管理使用的网卡选为业务口；管理口不参与镜像和桥接。

### 旁挂接线

交换机镜像目的端口 → `port1` 绑定的物理网卡；管理客户端 → `mgmt0`。
在交换机上配置需要审计的端口或 VLAN 镜像，接收口不得同时作为普通业务端口。
管理页面选择「旁挂」，镜像口选 `port1`，然后在 Linux 上另开终端运行：

```bash
sudo .venv/bin/python -m waf.dataplane
```

旁挂仅采集和审计，不丢包、不发 RST、不参与原始转发。正常请求标记为「旁挂已审计」，命中规则为「观察命中」。

### 串联接线

上游交换机 → `port1`；`port2` → 下游服务器 / 交换机；管理客户端另接 `mgmt0`。
管理页面选择「串联」，入口 / 出口分别选 `port1` / `port2`，使用同一命令启动数据平面。
程序创建专用 `wafbr0` 软件桥和 `bridge waf_guard` nftables 表；不会清空主机其他防火墙表。
TCP 80、8080 的报文进入 NFQUEUE 83，命中规则时拦截相关报文；观察模式仅记录。
桥接业务流量不使用 8300 代理入口，也不要求填写站点源地址。
运行期间队列未配置 bypass；进程异常丢失时，留存队列规则会使对应 HTTP 流量无法通过。
正常 Ctrl+C / SIGTERM 退出会删除本程序创建的规则和桥接，恢复原先业务网卡的 UP / DOWN 状态；物理串联链路会因此断开。
SIGKILL / 断电后应检查并清理残留资源，程序不会接管同名的既有 bridge / nftables 表。
这不是硬件断电直通方案，也没有自动主备切换。

管理页面根据配置指纹与工作进程心跳显示运行状态，15 秒没有心跳视为未运行。
控制面与数据平面必须使用同一个数据库路径；修改配置后重启数据平面。
每个数据库只允许一个数据平面进程。

### 检测和验证范围

- 当前识别 TCP 80 / 8080 的明文 HTTP/1.x；HTTPS、HTTP/2、HTTP/3 及其他端口不检测，仍按普通桥接流量转发。
- HTTP/1.x 使用 h11 解帧，支持请求头、分块传输和有限 TCP 乱序重组；IP 分片、TCP 重叠歧义、镜像丢包、连接中途接入等情况尚未完整覆盖。
- 最多 1024 个跟踪流，空闲 120 秒过期；每流乱序缓存最多 32 段 / 64 KiB，HTTP 头最多 64 KiB。
- 检测到恶意内容后丢弃对应报文，不缓存完整事务；已转发的前置片段不能撤回。复杂规避场景尚需专门的数据平面验证。
- 数据平面没有采集 HTTP 响应，审计状态码保存为 0，页面显示为「—」。
- 软件队列、SQLite 同步审计和 Python 检测尚未经吞吐压测，不能据此承诺线速或生产级防护。

# 多域名与多源站保护

复杂匹配：站点配置新增可视化规则编辑器，可按域名、访问端口、路径前缀及优先级选择多个后端源站。点击「新增匹配规则」，填写后保存；域名必须在受保护域名列表中。规则按优先级降序、精确域名优先、最长路径优先匹配，匹配不到才使用原域名源站池和默认源站。该功能用于反向代理入口，路径及查询参数原样转发。详见 `docs/USER_GUIDE.md`。

在「站点配置」填写受保护域名后，每个域名会生成独立的后端源站配置行。每行可填写最多 16 个 HTTP / HTTPS 地址（每行一个地址），支持内网 IP、域名及自定义端口。源站地址不含路径、用户名、密码或查询参数。修改后点击「保存站点配置」。

例如 `www.example.com` 对应 `http://10.0.0.11:8080` 和 `http://10.0.0.12:8080`，`api.example.org` 对应 `https://10.0.1.11`。不同域名独立选择源站，同一域名的多个源站按工作进程轮询；精确域名优先于单层通配符。后端保留用户访问的 Host，HTTPS 源站继续验证证书。

GET、HEAD、OPTIONS 在建立源站连接失败时依次尝试该域名的其他源站；读取失败、HTTP 错误响应及 POST、PUT 等请求不自动重试，避免重复提交。所有源站连接失败返回 502。此功能为请求时故障切换，不包含后台主动健康检查或会话粘滞。

独立源站留空时使用「默认源站地址」；均未配置返回 503。未纳入受保护域名的请求返回 403。HTTPS 证书仍按域名独立选择，前端证书与后端源站互相独立。配置保存在当前 SQLite 或 PostgreSQL 数据库中，兼容原有单源站配置。API 字段为 `domain_upstreams`，例如 `{"www.example.com":["http://10.0.0.11:8080","http://10.0.0.12:8080"]}`，其键必须同时存在于 `protected_domains`。
